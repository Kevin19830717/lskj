# AI 健康管理 · 慢病与癌症早筛平台 — 设计文档

> 基于「智能饮食健康秤」项目的扩展方案
> 目标：投合导师「癌症早筛 / 医学图像分析 / 生物医学 AI」研究方向
> 原则：**零侵入** —— 全部以新增文件 + 新增表实现，不破坏任何现有功能

---

## 一、现状与差距

现有系统已有能力：
- ✅ 体检报告**多模态 OCR**（`rag-service/routers/rag.py` 的 `parse-medical-report`，调用 qwen 视觉模型）
- ✅ `user_profiles.medical_reports` JSONB 字段 + `UploadMedicalReport` 接口
- ✅ 用户画像（年龄/性别/身高/体重/BMI）、饮食称重数据、RAG 检索与 AI 建议
- ✅ 前端成熟 UI 组件库（`Card` / `AppShell` / `AnimatedNumber` / `WaveLoader` 等）

**关键缺口（本方案的价值增量）**：
1. OCR 解析结果**不落库、不结构化** → 无法查询 / 对比 / 追踪
2. `medical_reports` 只是 `{报告类型: 字符串}` 的浅存储 → 无法做风险分析
3. **没有慢病 / 癌症风险分层引擎** → 这是挂靠「癌症早筛」的核心缺失
4. 没有**指标趋势追踪** → 无法做纵向健康分析（导师研究强调队列 / 纵向数据）

## 三、数据库设计（新增 2 张表，不影响现有表）

### 3.1 `medical_indicators` — 体检指标结构化存储

```sql
CREATE TABLE IF NOT EXISTS medical_indicators (
    id            BIGSERIAL PRIMARY KEY,
    user_id       INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    report_date   DATE NOT NULL,                 -- 体检日期
    category      VARCHAR(30) NOT NULL,          -- blood_pressure / lipid / glucose / uric_acid / liver / kidney / tumor_marker / blood_routine
    indicator_name VARCHAR(50) NOT NULL,         -- 指标名，如"空腹血糖"
    indicator_key  VARCHAR(50) NOT NULL,         -- 标准化键，如"fasting_glucose"
    value         NUMERIC(12,3),                 -- 数值
    value_text    VARCHAR(50),                   -- 原始文本值（如"<0.5"）
    unit          VARCHAR(20),
    normal_range  VARCHAR(50),                   -- 参考范围文本
    status        VARCHAR(10),                   -- normal / high / low / abnormal
    created_at    TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(user_id, report_date, indicator_key)
);
CREATE INDEX idx_medical_indicators_user_date ON medical_indicators(user_id, report_date DESC);
CREATE INDEX idx_medical_indicators_user_key   ON medical_indicators(user_id, indicator_key, report_date DESC);
```

### 3.2 `health_risk_assessments` — 风险评分结果

```sql
CREATE TABLE IF NOT EXISTS health_risk_assessments (
    id            BIGSERIAL PRIMARY KEY,
    user_id       INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    report_date   DATE NOT NULL,
    disease_key   VARCHAR(30) NOT NULL,          -- hypertension / diabetes / dyslipidemia / hyperuricemia / cancer_screening
    risk_level    VARCHAR(10) NOT NULL,          -- low / medium / high
    score         NUMERIC(5,2),                  -- 0~100 风险分
    evidence      JSONB DEFAULT '{}',            -- 触发的异常指标及理由
    suggestion    TEXT,                          -- 大模型生成的建议
    created_at    TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(user_id, report_date, disease_key)
);
```

> 两张新表通过 `user_id` 关联现有 `users` 表，**不改动任何现有表结构**。

## 四、核心：规则引擎设计（慢病 / 癌症早筛风险分层）

采用**医学参考范围规则 + 分级评分**，不依赖训练数据，7 天可控。

### 4.1 疾病维度与规则

| 疾病 | 关键指标 | 低风险 | 中风险 | 高风险 |
|---|---|---|---|---|
| 高血压 | 收缩压 / 舒张压 | <120/<80 | 120-139/80-89 | ≥140/≥90 |
| 糖尿病 | 空腹血糖 | <5.6 | 5.6-6.9 | ≥7.0 |
| 高血脂 | 总胆固醇 / 甘油三酯 / LDL | 正常 | 边缘升高 | 明显升高 |
| 高尿酸 | 血尿酸 | <360 | 360-420 | >420 |
| **癌症早筛** | 肿瘤标志物(AFP/CEA/CA199/PSA 等) | 正常 | 轻度升高 | 显著升高 + 需复查 |

### 4.2 风险评分逻辑（伪代码）

```python
def assess_risk(indicators: list, profile: dict) -> list[RiskResult]:
    results = []
    for disease in RULES:                    # RULES 为配置化的规则表
        abnormal = [i for i in indicators
                    if i.key in disease.related_keys and is_abnormal(i)]
        if not abnormal:
            continue
        score = sum(weight(i) for i in abnormal)   # 各异常指标加权求和
        level = "high" if score >= THRESHOLD_HIGH \
           else "medium" if score >= THRESHOLD_MED else "low"
        results.append(RiskResult(
            disease_key=disease.key,
            risk_level=level,
            score=score,
            evidence=[{key, value, range, status} for abnormal],
        ))
    # 癌症早筛特殊逻辑：任一肿瘤标志物升高即标记"建议专科复查"
    return results
```

### 4.3 大模型解读（复用现有 `call_responses_api`）

规则引擎给出**风险分层**后，把「异常指标 + 风险等级 + 用户饮食画像」喂给大模型，生成：
1. **通俗化解读**（用户能看懂）
2. **饮食干预建议**（复用现有 RAG，如高尿酸 → 低嘌呤饮食）
3. **就医提醒**（符合医疗安全规范，不做诊断结论）
