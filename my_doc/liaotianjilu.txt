一、项目概况与架构
================================================================================

项目名称：智能饮食健康秤 (Smart Scale)
项目路径：/home/ubuntu/lskj/

技术栈：
  - 后端：Go (Gin框架) 端口 8080
  - RAG服务：Python (FastAPI + httpx) 端口 8001
  - 前端：React + TypeScript + Vite + TailwindCSS v4 + Framer Motion
  - 数据库：PostgreSQL + pgvector
  - AI模型：阿里云百炼 qwen3.6-flash (OpenAI兼容 Responses API)
  - 反向代理：Nginx 端口 80

前端有两个版本：
  1. 旧版 HTML：/home/ubuntu/lskj/smart-scale-backend/frontend/ (已基本不用)
  2. 新版 React：/home/ubuntu/lskj/smart-scale-backend/frontend-react/ (主要使用)
     - 构建产物在 dist/ 目录
     - Nginx 指向 dist/ 目录提供静态文件

启动方式：
  bash /home/ubuntu/lskj/start.sh   # 启动所有服务
  bash /home/ubuntu/lskj/stop.sh    # 停止所有服务

RAG服务手动重启（需要带环境变量）：
  pkill -f "uvicorn app:app"
  cd /home/ubuntu/lskj/rag-service && source venv/bin/activate
  export DASHSCOPE_API_KEY=sk-07c88e8d2fe8470c934c19682c403467
  export DATABASE_URL=postgresql://postgres:321738392@localhost:5432/smart_scale
  export TEXT_MODEL=qwen3.6-flash
  export VL_MODEL=qwen-vl-flash
  export EMBEDDING_MODEL=text-embedding-v2
  nohup uvicorn app:app --host 0.0.0.0 --port 8001 > /home/ubuntu/lskj/logs/rag.log 2>&1 &

注意：start.sh 中设置了 set -e 已被移除，go mod tidy 和 pip install 添加了容错。
但 RAG 服务在 start.sh 中启动时可能丢失环境变量（之前出现过 "Illegal header value b'Bearer '" 错误），
如果 AI 聊天报错，需要手动用上面的命令带环境变量重启 RAG 服务。

前端构建：
  cd /home/ubuntu/lskj/smart-scale-backend/frontend-react && npx vite build
  然后 sudo nginx -s reload

主题色系统：
  - 绿色：仪表盘页、营养分析报告页（AppShell theme="green"）
  - 紫色：历史记录页、AI助手页、个人中心页（#667eea / #764ba2 渐变）
  - CSS变量 --primary 已从绿色改为紫色（在 index.css 中），影响全局 primary 色

三、待解决问题（重要！下一个 AI 需优先处理）
================================================================================

【问题1】AI页面滚动问题 — 仍未解决！
  描述：每次打开AI页面，聊天记录会从最顶端快速滑到底部，用户体验很差。
  已尝试的方案：
    1. requestAnimationFrame + scrollTop = scrollHeight（无效）
    2. isFirstRender ref 标记首次加载用 instant，后续用 smooth（无效）
  可能的原因：
    - 页面切换有 Framer Motion 的进入动画(AnimatePresence)，动画期间 scrollHeight 可能还不稳定
    - AppShell 组件可能有页面切换过渡动画导致渲染时机问题
    - useEffect 的依赖 [messages, loading, historyLoaded] 可能在首次渲染时就触发了 smooth 滚动
  建议方向：
    - 检查 AppShell 组件的页面切换动画，可能需要在动画完成后才设置 scroll
    - 用 setTimeout 延迟跳转（如 setTimeout 300ms）
    - 或者让消息列表初始就渲染在底部（CSS flex-direction: column-reverse）
    - 或者用 useLayoutEffect 替代 useEffect 在 DOM 绘制前设置 scroll

【问题2】个人中心排版 — 用户不满意！
  描述：用户说"不能只有一个主面板容器还要一些其他的显示，现在这个主面板显得很胖很臃肿"
  当前是左右两栏，用户可能想要：
    - 更紧凑的布局
    - 更多信息展示卡片（不只是编辑表单）
    - 头像区域不要太大
  建议方向：
    - 缩小头像尺寸（28→20）
    - 头像+昵称横排放在顶部，不要占整个卡片
    - 下面用多列卡片展示信息（身高/体重/BMI/目标/性别/年龄等）
    - 编辑表单可以折叠或放在下方
    - 参考常见 App 的个人中心设计：顶部横条 + 下方网格卡片

【问题3】AI 聊天响应速度
  描述：即使用了 qwen3.6-flash 模型，简单问题(如"你好")也要 16-18 秒
  可能原因：
    - previous_response_id 会加载之前所有对话历史作为上下文
    - 之前有一次超长回复（减脂建议几千字），每次都作为上下文处理
    - system prompt 中注入的用户数据和归档摘要增加了 token 数
  已优化：精简 system prompt、减少归档查询、max_output_tokens 2048、并行查询
  建议方向：
    - 考虑对简单问题(如"你好")不传 previous_response_id
    - 或者定期清理 response_id 重新开始对话
    - 或者换用更快的模型

【问题4】RAG 服务环境变量丢失
  描述：start.sh 重启后 RAG 服务可能丢失 DASHSCOPE_API_KEY，报 "Illegal header value b'Bearer '"
  原因：start.sh 中 RAG 服务启动时可能没有正确传递环境变量
  临时方案：手动带环境变量重启 RAG 服务（见上方命令）
  建议方向：修复 start.sh 确保 RAG 服务启动时继承所有环境变量，或使用 .env 文件
