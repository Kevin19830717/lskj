找到答案了。 ESP32 根本没走 80，它一直在直连 8080。

证据如下：

ESP32 请求没有经过 nginx（80端口），是直接打到 Go 后端的 8080 端口。

## 那为什么现在能用了？
不是端口变了，是 服务器重启后恢复了 。回顾一下上一个会话做的事情：

1. 重新编译运行了前后端 → Go 后端可能之前 crash 或没启动
2. 修复了 nginx 配置 → 前端页面刷新正常了
3. ESP32 一直在连 8080 ，之前失败大概率是 后端挂了或刚重启还没就绪
至于"热点不能用"的问题—— 移动运营商封 8080 并非 100% ，不同运营商、不同时段表现不同：

运营商 8080 出站 说明 中国移动 有时封 分省、分时段 中国联通 通常不封 你当前 IP 111.55 联通 中国电信 通常不封

你当前 ESP32 的 IP 111.55.210.78 是 联通 ，联通没有封 8080，所以能通。

## 建议
虽然现在能用，但 8080 在移动网络下 不稳定 （换个运营商或网络环境可能又不行）。建议你把 ESP32 的上传地址改成走 80 端口：

```
原来：http://106.53.198.194:8080/api/v1/weigh-in/record
改成：http://106.53.198.194/api/v1/weigh-in/record
```
nginx 已经在 80 端口代理了 /api/ 到 8080，这样无论什么网络都不会被封。只需要改 ESP32 固件里的 URL 配置（去掉 :8080 ），不需要改服务器代码。
