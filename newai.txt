一、项目概述
--------------------------------------------------------------------------------

四、前端架构详解（重要！两套系统并存）
--------------------------------------------------------------------------------
【关键理解】本项目有两套前端系统，通过Nginx路由分流：

1️⃣ React SPA (frontend-react/dist/) — 仅处理 "/" 和 "/dashboard"
   - "/" = LandingPage（登录/注册落地页）
   - "/dashboard" = DashboardPage（仪表盘，带新设计的紫色侧边栏）
   - 构建命令：cd smart-scale-backend/frontend-react && npm run build
   - 构建产物输出到 dist/，Nginx直接serve静态文件

2️⃣ 旧版 HTML 页面 (frontend/) — 处理 /records /reports /foods /profile
   - 每页独立HTML文件，共用 css/style-v15.css 和 js/app.js
   - 通过 <nav class="sidebar"> 内联侧边栏导航
   - 各页有独立 data-theme 属性决定内容区颜色主题

【Nginx 路由规则】(文件: /etc/nginx/sites-enabled/smart-scale.conf)
- listen 80; server_name _;
- root = frontend-react/dist/ (默认)
- location = /dashboard.html → 301 /dashboard
- location ~ ^/(records|reports|foods|profile)(\.html)?$ → root = frontend/ (旧版HTML)
- location /css/ /js/ /images/ → root = frontend/ (旧版静态资源)
- location /api/ → proxy_pass http://127.0.0.1:8080 (Go后端)
- location /rag/ → proxy_pass http://127.0.0.1:8001 (RAG服务)
- location / → try_files $uri $uri/ /index.html (SPA fallback)

⚠️ 重要：侧边栏导航在两个系统中不一致！
- React仪表盘的侧边栏点击"历史记录"等链接时使用 window.location.href = path
  跳转到旧版HTML页面，导致用户体验断裂（样式/侧边栏完全不同）
